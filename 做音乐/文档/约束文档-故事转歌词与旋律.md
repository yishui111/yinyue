# 歌词与旋律生成约束文档

> 用途:把本文档连同你的故事一起发给线上的 DeepSeek,让它产出「歌词 + 旋律乐谱」,
> 再交给本地唱歌模型 **YuE2** 合成整首歌(人声 + 伴奏,48kHz 立体声)。
> 本文档的输出格式与 YuE2 官方 API 严格对齐(仓库:`multimodal-art-projection/YuE`,HF:`m-a-p/YuE2-3B`)。

---

## 一、给 DeepSeek 的任务说明(复制下面整段发给它)

你是一名作曲家兼作词人。我将给你一个故事,你要把它改编成一首中文歌曲,并严格按以下格式输出,
**不要输出任何解释性文字,只输出两个代码块**。

**代码块 1**(```json 标注):歌曲请求文件 `song.json`。
**代码块 2**(```abc 标注):旋律乐谱文件 `score.abc`,必须遵守第二、三节的全部规范。

两种工作模式(由我在消息开头指定):
- **模式 A(词曲都由你写)**:同时输出 `song.json` 和 `score.abc`,其中 `cot` 填 `"full"`。
- **模式 B(你只写词,旋律交给唱歌模型自己作)**:只输出 `song.json`,`cot` 填 `"full"`,不输出 abc 代码块。

---

## 二、song.json 格式规范

```json
{
  "id": "night_train",
  "style": "Mandarin, gentle piano ballad, soft expressive female vocal, warm acoustic piano, soft strings, brushed drums, nostalgic and tender, 88 BPM",
  "lyrics": "[Verse]\n第一行歌词\n第二行歌词\n第三行歌词\n第四行歌词\n\n[Chorus]\n第一行歌词\n第二行歌词\n第三行歌词\n第四行歌词",
  "cot": "full",
  "seed": 42
}
```

| 字段 | 要求 |
|---|---|
| `id` | 短英文小写标识,如 `night_train` |
| `style` | **必须以 `Mandarin` 开头**;之后用英文写:曲风、人声(如 expressive female vocal / clear young male vocal)、主奏乐器、情绪、结尾写 `88 BPM`。BPM 必须与 abc 里的 `Q:` 完全一致,建议 70–120 |
| `lyrics` | 段落标签用 `[Verse]`、`[Chorus]`、`[Bridge]`、`[Outro]`,段落之间空一行。结构建议:Verse→Chorus→Verse→Chorus→Bridge→Chorus(可选)。**每行 7–12 个汉字**,避免生僻字、避免英文混入 |
| `cot` | 输出了 abc 乐谱就填 `"full"`(乐谱含和弦)或 `"melody"`(乐谱只有人声旋律、无和弦);没输出乐谱也填 `"full"` 让模型自己作旋律 |
| `seed` | 任意整数 |

## 三、score.abc 旋律规范(YuE2 原生方言,逐条硬性约束)

### 3.1 文件头(模板,固定写法)

```abc
X:1
T:
M:4/4
L:1/16
Q:1/4=88
V: Vocal clef=treble name="Vocal Melody" snm="Vocal"
V: Ins clef=treble name="Ins Melody" snm="Inst."
K:C
```

- `M:` 拍号(4/4 为主,可用 3/4、6/8);`L:1/16` 时 4/4 每小节 = **16 单位**,3/4 和 6/8 = 12 单位。
- `Q:1/4=88` 四分音符 BPM,必须与 song.json 的 style 里 BPM 一致。
- 两行 `V:` 必须同时存在:人声轨 `Vocal` + 乐器轨 `Ins`,两轨都只能是**单声部旋律**。
- `K:` 调号,标准大小调(如 `K:C`、`K:G`、`K:Am`、`K:F`)。

### 3.2 段落结构

- 用注释行划分段落,必须与 lyrics 的段落一一对应:`% verse`、`% chorus`、`% bridge`、`% outro`。
- 每个段落内部先写 `V: Vocal` 的旋律行(用 `|` 分小节),紧跟 `V: Ins` 的乐器行。
- 段落小节数:每行歌词配 1–2 小节;一段 4 行歌词 ≈ 4–8 小节。
- Ins 轨若不写器乐旋律,用全小节休止 `Z`(如该段 4 小节就写 `Z4|`)。

### 3.3 音符与八度(以 L:1/16 计)

| 写法 | 含义 |
|---|---|
| `C` | C4(中央 C),`D` `E` `F` `G` `A` `B` 同理为大字一组 |
| `c` `d` `e` | C5、D5、E5(小写升八度) |
| `C,` | C3(逗号降八度) |
| `c'` | C6(撇号升八度) |
| `C2` | C4 十六分音符(2 单位);`C4` 八分;`C8` 四分;`C16` 二分;`C32` 全音符 |
| `z4` `z8` | 休止符,单位同上 |
| `Z4` | 整休 4 小节 |
| `G8-G8` | 连音线(tie):两个同音高连成一个 8 拍音,**只在同音高之间使用** |
| `^F` `_B` `=F` | 升、降、还原号 |

- 允许的时值单位乘数只有:`1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48`;其他时值用 tie 拼接(如 10 单位 = `C8-C2`)。
- **每小节单位数必须精确等于拍号容量**(4/4=16、3/4=12、6/8=12,以 L:1/16 计),写完逐小节数一遍。
- **人声音域**:主体保持在 `C`(C4)到 `c`(C5)之间,高潮句可短暂到 `d` `e`(D5/E5);不要低于 `G,`,不要高于 `g`。中文演唱一字约一音,长音放在开口韵母的字上。
- 和弦进行建议:Verse 用 I–vi–IV–V 类平稳进行,Chorus 可加张力;每小节 1–2 个和弦。

### 3.4 和弦(写在 Vocal 行内,引号包裹)

允许的和弦类型(只能用这些):

```
大三和弦(不写后缀): C  G  F ...
m, dim, aug, 7, maj7, m7, dim7, m7b5, sus4, sus2, 6, m6, 7sus4, m(maj7)
转位低音: F#m7/C#  Gm6/Bb  A7/E
```

- 禁止:`Cmaj9`、`C13`、`A7alt`、`C:maj`、数字级数(如 `"V7"`)、自造记号。
- 和弦写在它开始的位置前:`"Am7"z16` 表示 Am7 从此处开始、人声休止半小节。
- 长音跨越和弦变换时必须用 tie 切开:`"G"G8-"Am"G8`(不允许同一长音下默默换和弦)。

### 3.5 禁止清单(出现任何一项即作废)

```
三连音/连音记号(3:2: 之类)、装饰音、滑音、圆滑线、
多声部叠音([C E] 这种)、反复记号(|: :|)、一二房子、
断奏记号(><)、w: 歌词行、自定义声部/指令、非常规调式
```

### 3.6 输出前自检清单

1. 每小节单位数逐小节核对(4/4 = 16 单位)。
2. abc 段落数、每段小节数与 lyrics 段落对应;每行歌词字数 ≈ 该行音符数(允许 ±2,不必逐字对齐)。
3. `Q:` 的 BPM = song.json 的 BPM。
4. 音域在 C4–G5 之间。
5. 未使用任何禁止记号;结尾没有悬空的连音线。
6. 歌词讲的是我给的故事:保留核心人物/情节/意象,不要泛泛抒情。

### 3.7 完整示例(一小段,供格式参考)

```abc
X:1
T:
M:4/4
L:1/16
Q:1/4=88
V: Vocal clef=treble name="Vocal Melody" snm="Vocal"
V: Ins clef=treble name="Ins Melody" snm="Inst."
K:C
% verse
V: Vocal
"G"C2D2E2G2E4G4|"Am"C2D2E2C2D4E4|"F"F2G2A2c2A4G4|"G"G2E2D2C2D4C4|
V: Ins
Z4|
% chorus
V: Vocal
"C"G2A2c2A2G4E4|"Am"A2c2d2c2A4G4|"F"A2G2A2c2d4c4|"G"G8-"C"G8|
V: Ins
Z4|
```

对应 lyrics 片段:

```
[Verse]
夜色落在窗台边
风把故事吹得远
灯一盏盏都熄灭
只剩心跳还没眠

[Chorus]
把回忆折成纸船
顺着月光漂向天
就算明天路更远
我也不说再见
```

## 四、产出后如何使用

1. 把两个代码块分别保存为 `song.json` 和 `score.abc`(UTF-8 编码)。
2. 交给本地工作台(或 YuE2 命令行)合成;模式 B 时只需要 `song.json`。
3. 合成后如果旋律不满意,只改 `score.abc` 重新合成即可,歌词与音色不受影响。
