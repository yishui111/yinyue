# 做音乐 · 原理说明

> 回答两个核心问题:**旋律到底是从哪来的?能不能"仿照"某一首歌来出新歌?**
> 并给出按成本排序的扩展路线。本文基于实际部署的 YuE2 官方文档与代码行为写成,
> 所有结论都可以在 `作品\` 的产物文件里验证。

---

## 一、一句话总结

本项目的分工是:**DeepSeek 当作曲家(写谱),YuE2 当歌手加乐队(照谱演出)**。
旋律不是从某个"曲库"里取出来的,也不是把哪首歌"训练进去"了——
**当前所有旋律都是当场生成的**:默认由 DeepSeek 按约束文档写成一份数字曲谱(ABC),
YuE2 再照着这份曲谱演唱并即兴编好伴奏。
"仿照某首歌"在原理上**支持**,途径是把那首歌转成 ABC 喂给 YuE2(推理时条件控制,不需要训练);
如果你想让它"自带"某歌手的作曲风格,那才需要动训练(LoRA 微调),是另一档工程。

## 二、一首歌在你机器上是怎么诞生的(完整数据流)

```
故事
 │  ⓪ 区块:约束文档作为系统提示词 + 故事 → DeepSeek API
 ▼
song.json(歌词+风格)  +  score.abc(旋律+和弦)      ← 旋律在这一刻被"写定"
 │  server.py 落盘到 作品\歌名\
 ▼
sing.py 启动 YuE2 流水线(YuE2Pipeline),内部四步:
 ① plan()              把请求转成模型输入;若给了 score.abc 就直接采用(跳过作曲)
 ② generate_semantic() 自回归模型(3B,类似 LLM)逐 token 生成"语义音乐序列",
                       严格对齐 abc 曲谱、歌词音节与风格描述
 ③ synthesize()        NAR 扩散/流匹配模型把语义序列合成为声学潜变量(这一步出人声细节与伴奏)
 ④ decode()            VAE 解码为 48kHz 立体声 audio.flac
 ▼
audio.flac + 最终采用的 score.abc + plan.json + result.json
```

要点:
- **曲谱是"白盒"**。合成产物里保留了模型实际采用的 `score.abc`,你可以打开修改(改几个音、
  换和弦),再对同一文件夹重新合成,旋律就按你改的来,歌词与音色不受影响。
- **`seed` 决定随机性**。同 seed + 同输入 = 同结果;换 seed = 同一首歌的另一个"演绎版本"
  (旋律骨架若来自你给的 abc 则不变,编曲与演唱细节会变)。
- 显存峰值实测 7.8~10.9 GB,1 分钟歌约 1 分钟合成(RTX 4080)。

## 三、旋律到底从哪来(问题 1 的答案)

旋律只有一个入口:**`score.abc`(或模型自己作的谱)**。具体到你的每次生成,分两种情况:

| 情况 | 旋律作者 | 怎么确认 |
|---|---|---|
| 你粘贴了 abc(或用 ⓪ 自动生成,默认含 abc) | **DeepSeek** 按约束文档写的 | 作品文件夹里的 score.abc 与你粘贴的一致 |
| 你只给了歌词(模式 B,abc 留空) | **YuE2 自己**在 ①plan 阶段作谱,再照谱唱 | 输出文件夹里的 score.abc 是合成时新产生的 |

### 为什么几首歌听起来旋律都差不多?

三个原因叠加,按影响大小排序:

1. **DeepSeek 作曲非常保守**(主因)。大语言模型写旋律是"组合常见套路":四四拍、级进音阶、
   对称乐句、C-Am-F-G 这类和弦循环——每次生成都高度趋同。你听到的"像",绝大多数是
   DeepSeek 的作曲习惯,而不是 YuE2 的问题。
2. **约束文档刻意把方言限得很窄**。为了保证"一定能唱、一定不报错",文档规定 4/4 拍为主、
   常用和弦表、十六分音符网格、固定音域——这是安全性和多样性之间的取舍(文末有放宽办法)。
3. **YuE2 是照谱演出的**。给了 abc,它就严格跟谱;即使让它自作曲(模式 B),
   它生成的也是"统计意义上最像流行歌"的旋律——因为它是在海量流行音乐上训练出来的模型,
   学到的是流行乐的普遍规律,**而不是记住了某一首具体的歌**。

### YuE2 里面"存"了歌吗?

没有。YuE2-3B 是在大量"歌词-音乐"配对数据上**预训练**出来的基础模型
(训练数据由 HKUST/M·A·P 等团队构建,与我们本地无关)。它和 ChatGPT 会写句子一样会写旋律——
靠的是学到的统计规律(什么音接什么音、什么和弦接什么和弦),不是曲库回放。
所以:**你的项目里没有任何一首现成歌的旋律;想"引入"某首歌的旋律,必须显式喂给它**(见下一节)。

## 四、"仿照某首歌"怎么做(问题 2 的答案)

先纠正一个概念:**"照着某首歌的旋律唱"不需要训练**。YuE2 的旋律入口就是文本曲谱,
推理时把目标旋律喂进去即可。真正的流程分三步,其中第 1 步的工具已存在但**尚未接入本工作台**:

```
① 提谱:任意一首歌的 mp3 → SheetSage2(官方配套转谱模型,音频→ABC)
        产物:score.abc(主旋律 + 段落结构)
② 改造:DeepSeek 拿着这份 ABC 做"旧曲新写":
        - 换词(按你的故事重新填词,音节数对齐原旋律)
        - 改旋律(只动你想动的音,保留骨架)——这一步是普通的文本编辑,人也可参与
        - 重配和声(cover 模式建议去掉原和弦,让伴奏跟新风格走)
③ 演唱:YuE2 以 abc=该曲谱 + cot="melody"(纯旋律跟随,伴奏自由)合成新歌
```

相关事实:
- YuE2 官方把这条链路叫 **cover(翻唱)**:`cot="melody"` + 无和弦曲谱 = 跟旋律不跟编曲;
  `cot="full"` + 带和弦曲谱 = 跟旋律也跟和声。仓库自带 `abc_tools.py strip-chords`
  可以一键去掉曲谱里的和弦(本项目 `YuE\skills\` 里就有这个工具)。
- **照谱演唱 ≠ 逐比特复制**:旋律骨架、音高节奏严格跟随,但咬字、转音、伴奏是模型即兴的,
  换 seed 会有不同"版本"。这正是"仿照而不是盗版翻录"的原因。
- SheetSage2 的模型与权重公开(`m-a-p/SheetSage2`,CC BY-NC 4.0,需配 MERT2 编码器;
  社区的 audio.cpp 也提供了免 Python 的 GGUF 版),但**本工作台当前没有集成这一步**——
  这是明确的扩展点,见下节路线 B。

## 五、扩展路线(按成本从低到高)

### 路线 D:提示层多样化(零成本,立刻可做)

针对"旋律都一样"最直接的解药,不用改代码:

- 每次换 `seed`(song.json 里)——同词曲的不同演绎;
- 故事里**点名要不一样的音乐要素**:"用小调""6/8 拍""慢板 70 BPM""用钢琴分解和弦"——
  DeepSeek 会把这些写进 style 和 abc;
- 把约束文档的和弦表放宽(加 m7、sus4、离调和弦,允许 G/Am/E 调性),给出的示例换成
  三种不同风格的示范曲,DeepSeek 的"套路"会立刻发散;
- 让 YuE2 自作曲(模式 B)与 DeepSeek 作曲(模式 A)**交替使用**,两种"作曲性格"完全不同。

### 路线 A:旋律库 + 选题合成(✅ 已实现)

把"仿照"做成产品功能,本工作台已落地:

1. `做音乐\旋律库\` 文件夹,每首一个 `曲名.abc`。曲库现有三类来源:
   - **手写**:开库自带 4 首风格迥异的曲谱(小调抒情 / 6/8 摇篮曲 / 欢快舞曲 / 中国风五声);
   - **曲谱工坊(页面 🎼 区块)**:描述想要的旋律 → DeepSeek 原创 → 官方校验通过后自动入库
     (校验不过会带着错误信息自动重试一次);
   - **传统曲批量转换**:`工具\曲谱转换入库.py` 从 TheSession(爱尔兰传统曲谱社区,
     旋律为公有领域)下载全量数据,自动转换成 YuE2 方言并校验入库:
     `python 工具\曲谱转换入库.py --count 8`(已用它入库 4 首传统曲)。
2. 页面 ⓪ 区块「旋律来源」下拉框:**自动**(DeepSeek 写词+作曲)或**指定曲库旋律**
   (DeepSeek 只按旋律的音符数填词,曲谱无和弦时自动用 cot="melody" 让伴奏自由发挥);
3. `server.py` 接口:`GET /api/melodies`(列曲库)、`GET /api/melodies/<名>`(取谱)、
   `/api/llm/generate` 接受 `melody` 参数、`POST /api/llm/melody`(曲谱工坊);
4. 产物照旧,`作品\歌名\` 里可追溯用的是哪份旋律。

### 路线 B:整曲翻唱链路(中等,接入 SheetSage2)

把"随便找一首 mp3 → 变成可仿照的旋律"自动化:

1. 部署 SheetSage2(独立 Python 环境,或 audio.cpp 的 GGUF 版免 Python);
2. `server.py` 加 `POST /api/transcribe`(上传 mp3 → 产出 score.abc 存入旋律库);
3. 用 `abc_tools.py inspect` 校验、`strip-chords` 出翻唱版;
4. 之后与路线 A 汇合:选题 → DeepSeek 填新词 → YuE2 演唱。

注意:转谱准确率不是 100%,产出曲谱需要人工过一遍(官方也这么建议);
转谱/伴奏分离对你的音频版权自行把握。

### 路线 C:LoRA 微调——真正把某歌手"训练成自带"(重量级)

前面三条都是"推理时控制",模型本体没变。若要让 **YuE2 自己作曲时**就带某个歌手/曲风的
旋律习惯,需要微调:

- YuE2 官方生态支持 **LoRA 训练**(社区 ComfyUI-FL-YuE2 提供完整的 AR + NAR 联合训练流程,
  消费级显卡可跑);
- 数据集:若干首目标风格的歌(音频 + 歌词 + 对应 .abc 曲谱,曲谱同样用 SheetSage2 批量转出);
- 训练产出 LoRA 适配器,合成时挂载,模型作曲的"性格"即被改变;
- 代价:要收集数据、跑训练(数小时级)、效果需调;**注意 YuE2 权重是 CC BY-NC 4.0,
  微调产物同样只能非商用**。

## 六、常见疑问

- **Q:seed 相同、故事不同,旋律会一样吗?**
  模式 B(模型作曲)下:故事影响歌词,风格与 seed 影响旋律,故事不同旋律可能碰巧相似;
  模式 A(DeepSeek 作曲)下:旋律完全由 DeepSeek 决定,seed 只影响 YuE2 的演唱演绎。
- **Q:为什么照着 abc 唱,两次合成还是有一点不一样?**
  abc 只锁定音高与节奏骨架;咬字、力度、转音、伴奏是模型即兴的。要锁定演绎,固定 seed。
- **Q:合成的歌能商用吗?**
  YuE2 权重许可证 CC BY-NC 4.0:**非商用**。个人娱乐、发视频平台自嗨没问题;
  商业发行需换 MIT 许可的 ACE-Step 等模型(旋律可控性会下降,见《模型调研结论.md》)。
- **Q:去哪验证本文说的东西?**
  曲谱:`作品\歌名\score.abc`(文本,可直接改);四阶段与耗时:`作品\歌名\result.json`
  的 timing 字段;翻唱与 abc 规范:YuE 仓库 `docs/covers.md` 与 `skills/yue2-music/references/abc-editing.md`。
