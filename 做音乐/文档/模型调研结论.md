# 「故事 → 歌词 → 旋律 → 整首歌」模型调研结论

> 调研日期:2026-09-25。硬件:RTX 4080 16GB / 32GB 内存 / G 盘余 206GB。
> 需求:工作台核心是**本地模型根据歌词 + 旋律把歌唱出来**,前面"编歌词和旋律"的思考环节可交给线上 DeepSeek(见同目录《约束文档-故事转歌词与旋律.md》)。

> **✅ 已部署完成(2026-09-25)**,日常用法见《使用说明.md》:
> - 环境:`D:\yue2\.venv`(torch 2.10.0+cu128,yue2-infer 0.1.6)+ `D:\yue2\weights`(权重 7.3GB;放固态是因为 G 盘为 USB 机械盘,加载太慢)
> - 入口:`唱歌.bat`(拖入作品文件夹)/ `自检.bat`(环境自检)/ `sing.py`(命令行)
> - 实测:模型加载 5~6s,**显存峰值约 7.9GB**(官方推荐 24GB 很保守,16GB 直跑无压力),1 分钟歌合成约 64s
> - 两条链路均已验证:①官方英文示例(模型自作曲) ②中文歌词 + 外部 ABC 曲谱(DeepSeek 路径)
> - 唯一适配:Windows 版 torch 无 flash-attention 内核,已在 `唱出来.py` 打补丁强制 cudnn/sdpa 注意力

## 一、结论(TL;DR)

**选定本地唱歌模型:YuE2-3B**(2026-09-14 前后发布,发稿时 HuggingFace 全球趋势第 1,质量对标 Suno v5/v6)。

- 严格意义的"输入一个故事直接出整首歌"的开源模型**不存在**——故事理解/写词是语言模型的事,没有音乐模型做这一步,所以按你预设的方案 b 走:故事 → DeepSeek(用约束文档)→ 歌词 + 旋律 → 本地模型唱。
- 但"根据歌词和旋律唱出来"这一本地核心环节,找到的 YuE2 比预期强得多:
  - **直接吃 ABC 文本乐谱当旋律输入**(`abc=` 参数),照着你给的旋律和和弦唱,伴奏自动编;
  - 输出**完整混音成品**(人声 + 伴奏,48kHz 立体声),不是干声;
  - 也能反过来**自己写旋律**(cot=full,输出可编辑的 score.abc)——工作台可以做成两种模式;
  - 官方 Python API 分四步(plan → generate_semantic → synthesize → decode),带 CLI 和 pip 包,天然适合封装成工作台;
  - 原生支持中文(标签 zh/en,官方演示含中文流行曲)。
- 显存:官方推荐 24GB,但你有三条路,16GB 的 4080 没问题(见下表)。

## 三、16GB 显存的三条运行路线

| 路线 | 说明 | 实测/依据 | 建议 |
|---|---|---|---|
| ① audio.cpp + Q8 GGUF | 纯 C++,免 Python;**支持 ABC 乐谱条件输入** | Q8 峰值 8.9GB,RTF≈0.2(3.7 分钟歌约 40–60 秒出) | 稳妥首选(资源占用最低) |
| ② 官方 Python pipeline(BF16) | `yue2` pip 包,功能最全,与官方 API 一致,便于封装工作台 | audio.cpp 侧 BF16 实测峰值 12.5GB;官方实现量级相近,16GB 大概率可跑,4 分钟长曲需验证 | 主选(先试,不行再退 ①) |
| ③ ComfyUI 官方节点 | 自动显存卸载,生态成熟 | Comfy-Org/YuE2 下载量 18 万+ | 不选(工作台要自研界面,包一层 Comfy 不如 ①② 直接) |

## 四、工作台架构(方案 b 落地图)

```
故事文本
   │  (线上 DeepSeek,输入 = 约束文档 + 故事)
   ▼
song.json(歌词+风格) + score.abc(旋律+和弦)      ← 模式 B 时只有 song.json,旋律由模型自己作
   │
   ▼  本地工作台(做音乐/)
┌─────────────────────────────────────────┐
│ 页面:故事输入 → 歌词/乐谱预览编辑 → 合成  │
│ 引擎:YuE2-3B(ABC 进 → 48kHz 整曲出)    │
│ 产物:audio.flac + score.abc + 生成记录   │
└─────────────────────────────────────────┘
   │  (可选,衔接已有系统)
   ▼
so-vits-svc / RVC(音乐模型/ 目录)→ 换成二次元角色音色
```

- 与你已有的"二次元唱歌换声"系统天然衔接:YuE2 出的是混音成品,可先分离人声再进 so-vits 换色。
- ABC 是纯文本,DeepSeek 输出、人工微调、程序解析都容易;工作台界面后续可加钢琴卷帘式乐谱编辑。

## 五、下一步部署清单(待你确认后执行)

1. 克隆 `multimodal-art-projection/YuE` 到 `音乐模型/做音乐/`(沿用你们便携 runtime/py312 形态;官方要求 Python 3.12)。
2. 下载权重 `m-a-p/YuE2-3B` + `m-a-p/YuE2-Vae`(约 7–8GB;国内可走 ModelScope 或 hf-mirror)。
3. 先跑官方 `examples/song.json` 验证 16GB 显存峰值;吃紧则切 audio.cpp Q8 GGUF 路线。
4. 写合成服务(HTTP API):入参 song.json + score.abc → 出 flac,并接 Gradio 工作台页。
5. 用约束文档实测一轮 DeepSeek → YuE2 全流程,按试听效果迭代约束文档。
